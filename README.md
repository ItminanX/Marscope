# MARSCOPE — Mission-Aware Route Intelligence for Mars
**ONE ROUTE. EVERY LAYER. ONE CREW BRIEF.**
NASA Space Apps Challenge 2026 · *Interplanetary Survival Guide: Martian Map* · Team DeltaX (Dhaka)

> **Pre-event concept prototype, not work produced during the official hackathon (Nov 14–15, 2026).**
>
> **Offline build (v2).** This version was prepared with network downloads intentionally disabled. It uses only files
> inside this project. The terrain is a **synthetic test fixture** in the official MOLA file format — **not NASA data** —
> and the app labels it SYNTHETIC everywhere.

## What MARSCOPE is
A decision-support map for Jezero crater (17.85–18.90°N, 76.95–78.20°E). It computes routes for three mission
priorities (traversability / science / balanced), explains every route segment in a **WHY?** evidence panel, shows where
each layer comes from, and prints a one-page **Crew Route Brief**. It is a planning aid, not a safety system.

## Run it (Python 3.10+; the user interface is already built)
```bash
pip install -r requirements.txt
python run.py                 # opens http://localhost:8000
```
Click **▶ DEMO MISSION**, then **NEXT ›** (8 steps, ≈ 2–3 min).
If FastAPI is not installed, `run.py` starts a Starlette-only server with the same API (Starlette, NumPy, SciPy,
Pillow, Pydantic and Uvicorn are still needed).

**No backend at all?** `cd frontend/dist && python -m http.server 8090`, open http://localhost:8090 — the app uses the
bundled snapshot of the Demo Mission and shows **OFFLINE SNAPSHOT**.

## Offline proxy-generation scripts (no internet needed)
| Command | What it does |
|---|---|
| `python scripts/make_fixture.py` | Re-creates the synthetic terrain fixture (deterministic, seed 42) |
| `python scripts/build_region.py` | Clips the region, computes slope/relief/hillshade, 1/512° + 1/1024° grid statistics, layer PNGs (incl. the shaded-relief SURFACE layer), the path slot and provenance → `data/processed/jezero/` |
| `python scripts/build_snapshot.py` | Freezes the Demo Mission API responses for the no-backend mode |
| `python scripts/check_local_data.py` | Lists which real source files are present in `data/raw/` |
| `python scripts/benchmark_routes.py` | Times route search on each grid on your computer |
| `python run.py --rebuild` | Runs build_region + build_snapshot, then starts the app |

Network downloads are **intentionally disabled in this version**. `scripts/fetch_mola.py` (needs internet) is kept for
later: on a machine with internet it downloads the real MOLA tiles; then `python run.py --rebuild` switches the whole app
to real data (the SYNTHETIC banner disappears). See `docs/DATA.md` for every intended source and where to put it.

## The honesty / status system
Every layer, grid, target and brief line carries a status word: **VERIFIED** (local copy of an identified official
source), **DERIVED** (calculated from identified inputs), **APPROXIMATE** (interpretation, placement or interpolation),
**ASSUMPTION** (configurable parameter), **SYNTHETIC** (generated by MARSCOPE — not NASA data), **CONCEPTUAL** (planned,
no data) and **DATA_UNAVAILABLE** (source file not in this build). A result is never stronger than its weakest input.

In this build, terrain and everything computed from it are SYNTHETIC; the shaded-relief SURFACE layer is not imagery;
finer routing grids are interpolation and add no detail; the violet dotted line is an illustration, not the Perseverance
path; CRISM is DATA_UNAVAILABLE; MEDA conditions and the global view are CONCEPTUAL. Slope limits and cost weights are
ASSUMPTIONS. Nothing is called safe.
